# AGENTS.md — manifest-generator

## Quick start

```bash
bun install          # installs all workspaces
bun run build        # clean → build packages → build demo
bun test             # runs all workspace tests
bun run lint         # lint:packages + lint:demo
```

Single-package shortcuts:

```bash
bun run --filter '@fsegurai/manifest-generator' pkg:build
bun run --filter '@fsegurai/manifest-generator' pkg:test
bun run --filter '@fsegurai/manifest-generator' pkg:test:coverage
```

## Project layout

```
packages/manifest-generator/   # the only real package (@fsegurai/manifest-generator)
  src/index.ts                 # library entrypoint (exports)
  src/cli.ts                   # CLI entrypoint (maybeRunCli guards test env)
  src/types.ts                 # shared types
  src/config.ts                # config file loading/merging (manifest-generator.config.{json,js,ts})
  src/init.ts                  # --init scaffolding (config file + sample docs structure)
  spec/                        # tests (bun:test, temp dir fixtures)
  vite.config.ts               # uses shared config from packages/.helper/config/vite-lib-config.ts
packages/.helper/config/       # shared Vite library build helper (ESM+CJS+UMD + tsc declarations)
demo/                          # Vite demo app, not a workspace package
scripts/test-all-packages.ts   # optional summary runner
```

## Build

- Vite library mode via shared helper (`packages/.helper/config/vite-lib-config.ts`).
- Outputs: `dist/index.esm.js`, `dist/index.cjs`, `dist/index.umd.js` + `dist/types/`.
- `pkg:build` also builds the CLI: a second Vite pass (`vite.cli.config.ts`, SSR/ESM) bundles `src/cli.ts` into `dist/cli.js` (the `bin` target; keeps the shebang, `js-yaml` and Node builtins external).
- Node builtins (`node:fs`, `node:path`, `node:util`) are **external** — never bundled.
- TypeScript declarations generated by `tsc --emitDeclarationOnly` (called from the Vite plugin).
- Declaration generation always logs "success" even if tsc exits with type-lib warnings.

## Test

- Uses **`bun:test`** (not Jest/Vitest). Tests live in `spec/`.
- All tests create and clean up temp directories (`fs.mkdtempSync` + `fs.rmSync`).
- Coverage enabled by default via `bunfig.toml` (threshold: lines 30%, functions 80%, statements 90%).
- Update snapshots: `bun test --update-snapshots`.
- Run all packages with summary: `bun run test:summary`.
- CLI tests mock `console.log`/`console.error` and pass a custom `exitFn`. `maybeRunCli()` returns `false` under `BUN_TEST` env.
- 184 tests across 4 test files (`cli.test.ts`, `config.test.ts`, `index.test.ts`, `init.test.ts`).

## CI flow

`test.yml`: lint:packages → test-types:packages → test:packages (library) + lint:demo (demo).
`checks.yml` → `build.yml`: `bun run prepare` per package + `bun run build:demo`.

`bun run test-types:packages` runs `tsc --noEmit` per package (`pkg:test-types`).

## Style

- **2-space indent** (Biome + editorconfig for JS/TS)
- **Single quotes**, semicolons required
- `comma-dangle: always-multiline`, `object-curly-spacing: always`
- `space-before-function-paren: never`
- Biome (`biome.json`) — handles both lint and format from one config; `noExplicitAny` is a warning, not an error; import organizing runs via Biome's assist actions
- Conventional commits (feat/fix/docs/refactor/test/chore/del)

## CLI details

- Entry: `packages/manifest-generator/src/cli.ts`. Run with: `bun ./packages/manifest-generator/src/cli.ts --help`.
- `maybeRunCli()` prevents auto-run under `BUN_TEST`/`NODE_ENV=test`/`VITEST`.
- Flags: `--discover`, `--validate`, `--recursive`, `--watch`, `--init`, `--all`, `--project`, `--route`, `--docs-root`, `--output`, `--docs-subfolder`, `--config <path>`, `--json`, `--dry-run`, `--quiet`/`-q`.
- Discovery: looks for `docs/` subfolder per project dir, falls back to direct `.md`/`.mdx` files.
- `--recursive` discovers projects in nested directories (stops at project roots).
- `--validate` checks frontmatter (date validity, conflicting flags, missing alternatives, unknown keys, duplicate `redirect` targets); output is colorized and TTY/`NO_COLOR`-aware.
- `--watch` polls for file changes and regenerates.
- `--init` scaffolds a config file + sample docs structure; prompts interactively when stdin is a TTY.
- `--validate`/`--discover`/`--watch`/`--init` are mutually exclusive.
- `--config <path>` loads an exact config file instead of auto-detecting `manifest-generator.config.{json,js,ts}`; that config supports `docsRoot`, `docsSubfolder`, `outputDir`, `recursive`, `exclude` (globs), and per-project `projects` overrides.
- Frontmatter keys (21 total, see `ALLOWED_FRONTMATTER_KEYS` in `index.ts`): `label`, `description`, `tags`, `keywords`, `order`, `isTitle`, `isParent`, `icon`, `iconType`, `badge`, `badgeColor`, `breadcrumbTitle`, `layout`, `redirect`, `externalUrl`, `deprecated`, `deprecatedAlternative`, `publishedAt`, `updatedAt`, `draft`, `hidden`.
- Output: `manifest.json` + `search-index.json` written to `--output` dir (or source root if omitted). In this repo, output lives at `docs/<version>/` (not inside `content/`). Items sorted by `order` then label. Null/false fields stripped via `cleanItem()`.
- Both outputs carry a `breadcrumb: BreadcrumbSegment[]` field (`{label, route}` per segment) on every item/entry — always present, ends with the item's own segment.
- Supports `.md` and `.mdx` files.
- Folder label: taken from the folder's `README.md`/`README.mdx`/`index.md`/`index.mdx` (first found, in that order) as `breadcrumbTitle` → `label` → formatted folder name. The same value is used for the folder's nav label, its own breadcrumb segment, and its descendants' breadcrumbs.
- `isMainModule()` resolves symlinks (`fs.realpathSync`), so the CLI also runs via `node_modules/.bin` and `npx`.

## Important constraints

- **Bun required** — not npm/pnpm. Lockfile is `bun.lock`.
- Node >=22, Bun >=1.3.0.
- `packages/.helper/` is excluded from workspaces — not a publishable package.
- `postbuild:packages` copies `LICENSE` into each package's dist.
